## Rate limiting

- `GET /api/analytics/periods` and `GET /api/analytics/revenue` use two rate-limit stages:
  1. A lenient pre-auth bucket `analytics:auth` (100 requests / 15 min per client) protects the token and business lookup. Unauthenticated requests return `401` before any business quota is consumed.
  2. After `requireBusinessAuth`, a per-business bucket `analytics:<businessId>` (30 requests / 15 min) limits report queries. The bucket is derived from the authenticated `req.business.id`, so businesses behind a shared IP/NAT have independent quotas and one business cannot fan out over many IPs to multiply its quota.
- Exceeding a limit returns `429 { "error": "Too many requests, please try again later." }`. Every response carries `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`, `X-RateLimit-Bucket` and `Retry-After`; on `401` responses the bucket header is `analytics:auth`.
